Una sigla que vamos a usar todo el curso

¿Qué es el WRF?

  • WRF = Weather Research and Forecasting model — un modelo numérico de predicción atmosférica de mesoescala, escrito en Fortran, usado en investigación y en pronóstico operativo en todo el mundo.
  • El WRF necesita datos de entrada (condiciones iniciales y de frontera) y produce datos de salida (la simulación en sí).
  • Este curso no enseña a correr el WRF — enseña a automatizar, con Python, todo lo que rodea esa ejecución: conseguir sus insumos, leer sus resultados, y comprobar que esos resultados sean creíbles.
Hacia dónde vamos

El curso en 6 módulos

  • Módulo 1 (hoy y mañana) — Python básico: la caja de herramientas.
  • Módulo 2 — Formatos de datos atmosféricos: NetCDF y GRIB.
  • Módulo 3 — Descarga automatizada de datos de entrada (ERA5, GFS).
  • Módulo 4 — Lectura y visualización de salidas del WRF (wrfout, el nombre típico de los archivos que produce el modelo).
  • Módulo 5 — Validación de resultados contra observaciones.
  • Módulo 6 — Todo integrado en un pipeline reproducible (proyecto final).
Todo lo que hacemos después —descargar ERA5, leer wrfout, calcular un RMSE— es, en el fondo, manipular arreglos numéricos con metadatos.

"Metadatos" aquí quiere decir: junto a cada número, información sobre qué representa (una fecha, una coordenada, una unidad). Sin eso, un arreglo de números es solo eso — números sin significado.

Por eso empezamos por los fundamentos de Python, no por WRF.

Entornos virtuales

¿Qué son y por qué instalamos desde un archivo versionado?

Concepto

Python es un lenguaje interpretado

A diferencia de Fortran (el lenguaje del WRF), que se compila antes de ejecutar.

  • Cada línea se traduce y ejecuta en el momento, no de una sola vez al inicio.
  • Ventaja: iterar rápido, probar ideas en segundos.
  • Consecuencia práctica: dos proyectos pueden necesitar versiones distintas de la misma librería (xarray 2023.1 vs. xarray 2024.6), y no siempre son compatibles entre sí.
El problema, con un ejemplo concreto

Sin entornos separados...

Proyecto A (enero)

  • Necesita xarray 2023.1
  • Se instala directamente en el sistema ("global"), sin aislar nada
  • Funciona bien... por ahora

Proyecto B (marzo)

  • Necesita xarray 2024.6, que cambió cómo lee ciertos archivos
  • pip install --upgrade xarray reemplaza la versión anterior
  • Proyecto A deja de funcionar, sin haber tocado su código
La solución

Un entorno virtual por proyecto

  • Miniconda crea una carpeta aislada con su propia copia de Python y de cada librería.
  • El entorno del curso se llama wrf2026.
  • base (el entorno por defecto) se deja intacto — WRF y su cadena de Python conviene mantenerlos separados de este entorno.

int, float, str, bool

  • int — números enteros: 24, -3
  • float — números con decimales: 18.5, 1013.25
  • str — texto: "2026-01-15"
  • bool — verdadero/falso: True, False
🧮

¿Cuánto da 0.1 + 0.2 en Python?

¿Exactamente 0.3? Pruébenlo mentalmente antes de ver la respuesta.

→
Respuesta

Punto flotante: precisión limitada

>>> 0.1 + 0.2
0.30000000000000004

>>> 0.1 + 0.2 == 0.3
False
¿Por qué importa?

Nunca comparar decimales con ==

  • La computadora guarda los decimales en binario, y muchos (como 0.1) no se pueden guardar exactos, igual que 1/3 no se puede escribir exacto en decimales (0.333...).
  • No es un defecto de Python: pasa en casi todos los lenguajes.
  • La forma correcta: comparar con una tolerancia: np.isclose(0.1 + 0.2, 0.3) da True.
  • Lo vamos a necesitar en el Módulo 5, al comparar el WRF con observaciones.
Modelo mental

Una variable es una etiqueta, no una caja

  • En Python, una variable apunta a un objeto en memoria; no lo "contiene", como sí ocurriría en una caja física donde guardar algo distinto reemplaza lo anterior.
  • Si el objeto es mutable (como una lista o un diccionario), modificarlo desde una función afecta al original — no a una copia.
  • Si el objeto es inmutable (un número, un texto, una tupla), no hay este riesgo: cualquier "cambio" en realidad crea un objeto nuevo, y el original queda intacto.
  • Esto explica un tipo de error muy común entre quienes recién empiezan: modificar sin querer un dato que se pensaba estaba "a salvo" fuera de la función.
Ejemplo

Mutabilidad en acción

def agregar_medicion(lista, valor):
    lista.append(valor)  # modifica la lista original
    return lista

temperaturas = [18.2, 19.0, 20.1]
resultado = agregar_medicion(temperaturas, 21.5)

# temperaturas YA CAMBIÓ, aunque no se reasignó explícitamente
print(temperaturas)  # [18.2, 19.0, 20.1, 21.5]

Estructuras de datos

Listas y diccionarios: cuándo usar cada una

Acceso a datos

Lista (posición) vs. diccionario (clave)

Lista — por posición

  • temperaturas[2]
  • Frágil: hay que recordar el orden
  • Útil cuando el orden mismo importa

Diccionario — por clave

  • temperaturas["2026-01-03"]
  • Autoexplicativo
  • Acceso en tiempo prácticamente constante (tabla hash)
Anidamiento

Listas de diccionarios

estaciones = {

Flujos de control

Condicionales y bucles: reglas y repetición

Condicionales

if / elif / else como reglas físicas

def clasificar_precipitacion(valor_mm):
    if valor_mm <= 0.1:
        return "sin lluvia"
    elif valor_mm <= 2.0:
        return "llovizna"
    elif valor_mm <= 15.0:
        return "moderada"
    else:
        return "fuerte"
Bucles

for / while — iterar sin controlar índices

  • for temp in temperaturas: en vez de for i in range(len(temperaturas)): cuando no se necesita la posición — más corto y más difícil de escribir mal.
  • Evita errores de "off-by-one"
    • Es el clásico error de contar mal el inicio o el final de un rango — por ejemplo, olvidar que en Python el conteo empieza en 0, no en 1, y terminar leyendo un dato de más o de menos.
    • Al escribir for temp in temperaturas: ese error deja de ser posible, porque nunca se maneja el índice a mano.
  • while cuando no se sabe de antemano cuántas iteraciones harán falta — por ejemplo, repetir un intento de descarga hasta que tenga éxito (idea que se retoma en el Módulo 3).

Funciones y organización

El bloque de construcción de todo el resto del curso

Abstracción

Una función = nombre + entradas + salida

  • Permite reutilizar lógica sin copiar y pegar código: se escribe una vez, se usa muchas veces con distintos datos.
  • Desde el Módulo 3 en adelante, cada tarea del pipeline (descargar, graficar, validar) se encapsula en funciones.
  • Scope (alcance): una variable definida dentro de una función no existe fuera de ella.
    • Ejemplo: si dentro de calcular_promedio() se crea una variable suma, esa suma desaparece apenas la función termina — no se puede usar después, afuera.
    • Esto evita efectos secundarios inesperados: dos funciones distintas pueden usar el mismo nombre de variable internamente sin pisarse una a la otra.
