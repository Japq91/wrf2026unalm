Reanálisis vs. pronóstico operativo

Qué fuente usar depende de si el evento ya pasó

Tres fuentes

ERA5 vs. GFS vs. FNL

ERA5 (reanálisis)GFS (pronóstico operativo)
Qué esUn modelo ajustado con observaciones: la mejor estimación de lo que pasóUn modelo que calcula el futuro, corrido 4 veces al día (00/06/12/18 UTC, la hora universal: en Perú son las 19/01/07/13 h)
Consistencia temporalLa misma metodología en todo el registro histórico (desde 1940)Cambia con los años (resolución, versión del modelo)
Caso de usoReproducir un evento ya ocurrido, estudios de climaSimular un evento próximo, replicar un pronóstico real
Quién lo produceCopernicus / CDS (Climate Data Store, el servicio europeo de acceso a datos climáticos)NCEP (National Centers for Environmental Prediction), parte de NOAA (la agencia atmosférica y oceánica de EE.UU.)
🌦️

Quiero simular una lluvia intensa de marzo de 2023. ¿ERA5 o GFS?

Respondan antes de pasar.

ERA5: el evento ya ocurrió, y el reanálisis usa observaciones de esos días que un pronóstico hecho antes no tenía.
Cuándo usar cada una

Evento pasado o evento futuro

  • Para reproducir con fidelidad un evento ya ocurrido, ERA5 suele ser la mejor opción, aunque exista un pronóstico de GFS archivado para esa fecha.
  • GFS se usa cuando el evento todavía no ocurrió al momento de correr el WRF.
Una tercera fuente

FNL (Final Operational Global Analysis)

  • Es el análisis inicial de cada corrida de GFS, que guarda y publica NCAR (un centro de investigación de EE.UU.).
  • Sirve para eventos recientes, cuando ERA5 todavía no se publicó (ERA5 sale con unos días de retraso).
  • No tiene librería de Python como Herbie o cdsapi. Se descarga por HTTPS, sin cuenta, con un script csh que recibe la fecha.
El script

descarga_FNL.csh

# tcsh descarga_FNL.csh AAAAMMDD
set baseurl = "https://osdf-director.osg-htc.org/ncar/gdex/d083003/$year/$year$month"
set filelist = ( \
  $baseurl/gdas1.fnl0p25.${date}00.f00.grib2 \
  $baseurl/gdas1.fnl0p25.${date}00.f03.grib2 \
)
while($#filelist > 0)
  wget --no-check-certificate -N $filelist[1]
  shift filelist
end

No hace falta entender cada línea: el script arma la dirección web con la fecha y descarga los archivos con wget.

Otra fuente, de otro tipo

SENAMHI: lo que midieron las estaciones

  • ERA5, GFS y FNL son modelos: un valor por celda de grilla, para todo el planeta. Son la entrada del WRF.
  • Los datos de SENAMHI son mediciones en un punto. No entran al WRF; los usamos para comparar con lo simulado (Módulos 5 y 6).
  • Vienen como texto (;), en hora local de Perú (UTC−5) y con huecos marcados S/D («sin dato»).
Descarga de SENAMHI

Un paso lo hace una persona

  • El portal pide una verificación «no soy un robot» en cada descarga.
  • station-hist abre el navegador, la persona pasa la verificación y el script hace el resto.
  • Lo que el sitio pide hacer a mano, lo hacemos a mano.

2

Herbie

GFS, ECMWF y otros modelos, desde varios servidores

Para qué sirve

GFS está en varios lugares a la vez

  • GFS se publica en el portal de NOAA (NOMADS) y en copias en la nube de Amazon y Google.
  • NOMADS guarda solo los últimos días; las copias en la nube guardan años.
  • Cada uno usa direcciones distintas, y cambian con el tiempo.
  • Con Herbie indicas modelo, fecha y variable, y la librería busca dónde está el archivo.
En código

Herbie en 3 pasos

from herbie import Herbie

h = Herbie("2026-07-20 00:00", model="gfs", product="pgrb2.0p25", fxx=6)
ruta = h.download()          # trae el GRIB2 completo
ds = h.xarray(":TMP:2 m")    # decodifica con cfgrib -> Dataset
El parámetro fxx

fxx: cuántas horas hacia adelante

  • Cada corrida de GFS arranca a una hora fija (00, 06, 12 o 18 UTC) y calcula hacia adelante.
  • fxx=0 es el estado inicial de esa corrida (el análisis), y trae datos como cualquier otra hora.
  • fxx=6 es lo que el modelo calcula 6 horas después de arrancar.

cdsapi: pedir y esperar turno

Por qué una descarga de ERA5 puede quedarse esperando

La cola del CDS

El CDS no responde al instante

  • El cliente cdsapi envía una solicitud (variable, nivel, fecha, área, formato).
  • El servidor la pone en cola y la procesa cuando le toca: a veces en segundos, a veces en varios minutos.
  • Esperar es normal. Un script puede quedarse esperando mientras uno hace otra cosa.
Estructura de una solicitud

cdsapi.Client().retrieve(...)

import cdsapi
client = cdsapi.Client()
client.retrieve(
    "reanalysis-era5-single-levels",
    {
        "variable": ["2m_temperature"],
        "year": "2026", "month": "01", "day": "15",
        "area": [10, -82, -20, -66],  # norte, oeste, sur, este
        "format": "netcdf",
    },
    "era5.nc",
)
⏳

¿Cuánto puede tardar una solicitud a cdsapi?

¿Segundos? ¿Minutos? ¿Depende de algo que ustedes controlen?

Depende sobre todo de cuánta gente esté pidiendo datos en ese momento, y algo del tamaño del pedido. La misma consulta puede tardar distinto otro día.

¿En qué orden va area en la solicitud?

[norte, oeste, sur, este]. Anótenlo para la práctica.

Con el orden cambiado no siempre hay error: puede llegar otra área sin aviso.
